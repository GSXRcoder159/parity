Parity score

ParityBench replays a corpus of API sequences against the Parity twin, an open-source Stripe-compatible Billing server, and compares every response with a recording of the same sequence on the real Stripe sandbox (the oracle).

Any score without the noise floor and ceiling is invalid.

The twin is scored nightly on the whole corpus. Each night re-records at most a seventh of it, as much as the sandbox read budget allows, so the oracle is at most 7 days old and drift on any sequence is detected within 7 days whenever every night can afford a seventh. Each night's point from 2026-09-28 on in data/curve.json records the oracle's actual maximum age (oracleMaxAgeDays).

Nightly curve

Share of agreeing steps (L3) and sequences (L4: every step at L3, the same event types, and, from method m2, no event created before one the sandbox always creates first), with 95% Wilson intervals. The ceiling is the agreement of two real sandbox recordings of the same sequences: no server can be measured above it. A “surface-added” mark means the twin's scope grew that night, so a jump there is not alignment.

  • L3 value (per step)
  • L4 sequence
  • 95% Wilson interval
  • ceiling (noise agreement)

Per stratum: train vs held-out

Held-out templates are never shown to the align loop; they only gate its patches. L1 status, L2 shape, L3 value per step; L4 per sequence. Ceiling = noise agreement; floor = 100% − ceiling.

Automation ratio

Automatic: an align-loop patch that edits only the twin's data files, for a value the oracle shows deterministically, applied when the held-out gate passes. Assisted: a code change proposed by the loop and merged after review. Surface-added changes are scaffold work and count as neither.

Units. The H2 ratio (at least 60% of applied patches automatic) counts patches: one automatic patch is one JSON-pointer edit to a data file, and one assisted patch is one merged pull request. One pull request can fix what many pointer edits fix, so each class also reports the train divergences it removed: the held-out gate's train divergence count before the change minus after it, from the sealed log.

  • share of patches (H2)
  • share of train divergences removed

Changelog

Files, pointers, PR numbers and notes only, never values. Train divergences removed = the gate's count before the change minus after it.
