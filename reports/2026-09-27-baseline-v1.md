### Nondeterministic paths

There are 3 divergent steps, all VALUE_MISMATCH, on 2 paths. Both paths are in train templates, so their values could be opened. None of the six held-out templates diverged.

| Path | Where (pairs) | Cause |
|---|---|---|
| `GET /v1/invoices` → `$.data[*].next_payment_attempt` | clock-declined-renewal (#30), step 13, seeds 1 and 2 | **The sandbox schedules the first retry of a declined renewal at a varying delay.** The declined attempt itself (`status_transitions.finalized_at`) sits at the same clock time in both runs. The retry lands 42.2 to 45.8 hours after it across the 20 oracle seeds, over the same range for monthly and yearly prices. The same seed gets a different delay in each run (seed 1: 42.2 h vs 44.0 h; seed 2: 42.9 h vs 43.7 h). `timestamps` normalizes to whole-hour offsets, so a spread of hours shows up as a value difference: 1 h for seed 2 and 2 h for seed 1. Which retry rule produces the spread is not established. The account's retry settings, which Smart Retries or a fixed schedule could govern, were not read |
| `GET /v1/charges/{id}` → `$.payment_method_details.card.electronic_commerce_indicator` | refund-full (#8), step 7, seed 1 | **A Visa charge's ECI takes one of two values, and nothing the sequence sends selects which.** The two runs send the same requests with the same test card, and neither uses 3-D Secure. Of the pair's 3 Visa charges (refund-full seed 1, expand-paths seeds 1 and 2), 2 agree and 1 differs. The 20 oracle seeds of refund-full and expand-paths show both values on Visa; Mastercard charges carry null. This is a simulated card-network value, the same kind as those the `card-network-opaques` rule already masks. v1.3 does not cover this field |

`summarize` relabels a target divergence on the same template, step and path as NONDETERMINISTIC. The align loop's noise set (`noiseFromRuns`: every pair of clean sandbox recordings of a sequence started under an hour apart) now holds both paths, so the loop keeps them out of mechanical patches.

### H0 verdict

**The noise floor passes.** Plan §1, H0: "≤3% at value level after normalization". The pooled L3 floor is 0.7% [0.2–1.9], so even its upper bound is under 3%. The kill criterion (>10%: report per stratum and exclude time-dependent paths) is not met, overall or in any stratum's point estimate. The risk-table row for the clock stratum (">10% on clock stratum → score it separately") is not met either: its L3 floor is 2.0%. One caveat: **the clock stratum's L4 ceiling is 75% [40.9–92.9]** on this pair, because the declined-renewal retry time differs in both seeds. A twin can match #30's L4 only by chance until the retry time is normalized or tolerated.

H0's throughput half was decided in W0 (non-clock) and on 2026-09-27 (clocks, `reports/2026-09-27-clocks.md`).

## H1 verdict

**Confirmed on 600 sequences.** H1 (plan §1): "best existing twin <80% sequence-level agreement on the stateful/error corpus".
- stripe-mock L4 is 0.0% [0.0–0.6] over 600 sequences. Its errors stratum is 0.0% L4 [0.0–6.0] at 41.1% L1.
- localstripe L4 is 0.0% [0.0–3.1] on the 120 sequences it can serve. It cannot run any errors, refunds, cancellation, events, proration or clock template.
- The sandbox agrees with itself at 95.0% L4 [86.3–98.3] on the noise pair, which covers all 10 strata. Its 100% L1 and 99.3% L3 set the ceiling.

The gap is not noise. The verdict would need an L4 above 80% on some target, and every upper bound here is ≤3.1%. The PM ruling of 2026-09-26 accepted H1 on the 88-sequence oracle. This is the full-corpus confirmation that the ruling left as the W1 residual.

## Reproduce

Anyone with their own sandbox key can re-run this. The exact commands are in [`docs/plan/impl/baselines.md`](../docs/plan/impl/baselines.md) §6 (oracle and noise pair) and §7 (this report). In short:

```sh
# .env: STRIPE_API_KEY=<your sandbox sk_test_ key>; PARITY_DATA_DIR=<private dir for raw recordings>
node src/cli.ts record --target sandbox --seeds 1-20 --concurrency 8
node src/cli.ts record --target sandbox --name noise-a --seeds 1-2 && node src/cli.ts record --target sandbox --name noise-b --seeds 1-2
node src/cli.ts oracle build
node reports/baseline.ts pair "$PARITY_DATA_DIR/oracle.jsonl" <oracle-subset> <partner> <noise-a run>   # then: compare
docker run --rm -d --name parity-stripe-mock -p 12111-12112:12111-12112 stripe/stripe-mock@sha256:ff32647993847be491e68533e2881c90434fa8d5df40246ee5f7d41253422081
node src/cli.ts bench http://localhost:12111 --oracle "$PARITY_DATA_DIR/oracle.jsonl" --out recordings/<date>/v1-bench-stripe-mock
```

Then `reports/baseline.ts surface` → `bench http://localhost:8420` for localstripe, and `summarize` for the JSON. The stripe-mock bench takes about 37 minutes, because `bench` keeps the templates' sandbox waits (up to 600 s in #30) against every target. Raw recordings and every `compare`/`bench` output hold Stripe response values. Keep them out of git (C3).
