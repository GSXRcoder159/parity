# Implementation plan: ParityBench harness (W0 + W1 core)

Spec (authority): `docs/plan/2026-09-25-parity-mvp-plan.md` §3.1, §4, §5 W0/W1. Status: `docs/plan/STATUS.md`.
Contract: `src/types.ts` (Step, Template, Sequence, StepRecord, Recording, Divergence, Gen). Generator: `src/gen.ts`.

## Global Constraints

- TypeScript run directly by Node ≥22.18 (type stripping; no build step). Relative imports use explicit `.ts` extensions; type-only imports use `import type` (`verbatimModuleSyntax`). `npx tsc -p tsconfig.json` must pass.
- Tests: `node --test test/*.test.ts` with `node:test` + `node:assert/strict`. Unit tests never touch the network except a local `node:http` server started by the test. Live Stripe tests run only when `PARITY_LIVE=1` and skip otherwise.
- No new runtime dependencies. Dev dependencies only with a stated reason in the report.
- Sandbox target: base URL `https://api.stripe.com`, key from env `STRIPE_API_KEY` (CLI loads `.env` via `process.loadEnvFile` when present). Never print, log, record, or commit the key. `.env` is never staged.
- Every request to every target sends `Stripe-Version: 2026-08-26.dahlia` and `Authorization: Bearer <key>` (non-sandbox targets default key `sk_test_parity`).
- Sandbox traffic is capped by a shared token bucket at **20 requests/second**, including event polling. Never load-test. 429s are retried at most 3 times (1 s, 2 s, 4 s) and counted in the recording.
- Minimal code (ponytail): no abstractions with one user, no config for constants; mark deliberate ceilings with a `// ponytail:` comment.
- Commits: one or more per task, message ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Stage only your task's paths (`git add <paths>`); never `git add -A` (other tasks may be running in the same tree). If `git commit` hits `index.lock`, wait 2 s and retry.
- Do not edit `src/types.ts` unless the task says so; if you must, keep the change minimal and list it under concerns.

## Task 1: Sequence runner

**Paths:** `src/bench/run.ts`, `src/jsonl.ts`, `test/run.test.ts`

Implement, in `src/bench/run.ts`:

- `export interface Target { name: string; baseUrl: string; apiKey: string; rps?: number; eventWaitMs?: number }`. `export function sandboxTarget(apiKey: string): Target` → `{ name: "sandbox", baseUrl: "https://api.stripe.com", apiKey, rps: 20, eventWaitMs: 3000 }`.
- `export function encodeForm(params: Record<string, unknown>): string` — Stripe nested form encoding: objects `a[b]=v`, arrays indexed `items[0][price]=v`, booleans `true`/`false`, numbers as decimal strings, `null` → empty string (Stripe's "unset"), `undefined` keys omitted. Brackets may be left unescaped; values are `encodeURIComponent`-escaped. Key order = insertion order.
- `export function resolveRefs(value: unknown, bound: Record<string, unknown>, runNonce: string): unknown` — deep-resolves strings per the `Step` doc in `src/types.ts`: ref grammar `\$([A-Za-z_][A-Za-z0-9_]*)((?:\.[A-Za-z0-9_]+)*)`; `$run` → `runNonce`; a string that is exactly one ref returns the raw value (any type); otherwise interpolate as strings. Numeric segments index arrays. Unresolvable ref → throw `Error("unresolved ref $c1.id")`.
- `export function createLimiter(rps: number): () => Promise<void>` — token bucket, capacity = rps, shared by all concurrent sequences of one target.
- `export async function runSequence(seq: Sequence, target: Target, opts: { take: () => Promise<void>; runId: string }): Promise<Recording>`:
  - `export function runNonce(runId: string, seqId: string): string` = `${runId}-${seqId}` with non-alphanumerics replaced by `-`; `runSequence` uses it (Task 3 imports it for normalization).
  - For each step: honor `waitMs`; resolve path/params/headers (on unresolved ref: push a `StepRecord` with `status: 0`, `body: null`, `error`, do not send, continue with the next step); GET/DELETE send params as query string, POST as `application/x-www-form-urlencoded` body; record status, parsed JSON body (fallback `{ _raw: text }`), `resHeaders` subset `request-id`, `idempotent-replayed`, `stripe-version` (only those present), `ms`, and the resolved request `headers` you set from the step (never Authorization). Bind `step.ref` to the response body (even for non-2xx; refs into a failed body will simply be unresolvable later). Transport errors → `status: 0`, `error`.
  - After the steps: collect events unless `target.eventWaitMs === 0`… see next bullet.
  - Events: gather every string anywhere in the step response bodies that matches `^[a-z]+(?:_[a-z]+)*_(?=[A-Za-z0-9]*[A-Z0-9])[A-Za-z0-9]{10,}$` (tail must contain an uppercase letter or digit, so enum values like `create_prorations` never match) into an id set. Wait `eventWaitMs` (default 3000 for sandbox, 200 otherwise), then poll `GET /v1/events?created[gte]=<startSec-60>&limit=100` following `has_more`/`starting_after` pagination; keep events whose `data.object.id` or `data.object.customer` is in the id set. Repeat polling every 2 s until the kept count is unchanged across two consecutive polls or 15 s have passed since the first poll. If the events endpoint returns non-200, record `events: []`. Sort kept events by `created` then `type`.
  - `Recording.target` = `target.name`; `ms` = wall time; `startedAt` ISO.
- `export async function runCorpus(seqs: Sequence[], target: Target, opts: { concurrency: number; runId: string; onRecord?: (r: Recording) => void }): Promise<Recording[]>` — fixed-size worker pool over `seqs`, one limiter per call (`createLimiter(target.rps ?? 1000)`), results returned in input order.
- 429 handling per Global Constraints; count retries in an optional `retries?: number` field on `StepRecord` (add this one optional field to `src/types.ts`; it is allowed by this task).

`src/jsonl.ts`: `writeJsonl(path, rows)` (creates parent dirs, one JSON per line) and `readJsonl<T>(path): T[]`. Nothing else.

Tests (`test/run.test.ts`), against a local `node:http` server the test starts: encodeForm cases (nested object, indexed array of objects, boolean, null, number); resolveRefs (exact ref keeps type, interpolation, numeric index, `$run`, unresolved throws); runSequence end-to-end against the local server (refs from step 1 used in step 2's path and params, POST body is form-encoded, GET params in query, headers recorded without Authorization, unresolved ref yields status 0 and later steps still run, events filtered by id set via a fake `/v1/events`, 429 retried then succeeds); limiter enforces rate (e.g. 10 takes at rps 5 take ≥1 s). One live smoke test (`PARITY_LIVE=1`): a 3-step sequence (create customer, retrieve `$c1.id`, delete) against the sandbox asserting statuses 200/200/200 and that `customer.created` appears in `events`.

Template rules (these keep the oracle clean and the sandbox within limits):
- Every sequence creates its own objects; never depend on pre-existing account data.
- Every list call is scoped so that only this sequence's objects can appear: `customer=`, `subscription=`, `product=`, `payment_intent=`, or `email=` with a per-sequence email. Never list account-global collections unscoped.
- Emails/names/metadata are deterministic from the generator: e.g. `parity+<template>-<n>@example.com` where `<n>` comes from `g.int`. Use `$run` only inside `Idempotency-Key` headers.
- Payment methods: attach Stripe test tokens (`pm_card_visa`, `pm_card_mastercard`, `pm_card_chargeDeclined`, …) with `POST /v1/payment_methods/<token>/attach` and bind the result; set `invoice_settings[default_payment_method]` on the customer or `default_payment_method` on the subscription.
- Prices may be created inline via `product_data[name]`. Amounts from the generator in realistic ranges (e.g. 500–50000 cents); currency `usd` (occasionally `eur`).
- No probe creates more than 5 invoices on one subscription. No test clocks in #1–#15.
- To find the payment for a subscription's first invoice use `GET /v1/payment_intents?customer=$c1.id` (or `GET /v1/charges?customer=`); on API version 2026-08-26.dahlia `invoice.payment_intent` no longer exists.
- Invoice preview endpoint is `POST /v1/invoices/create_preview` (the `upcoming` endpoint is removed).
- Error steps are part of the probe: they must deterministically produce the intended 4xx.

## Task 3: Normalization, comparison, score, report

**Paths:** `src/bench/normalize.ts`, `src/bench/compare.ts`, `src/bench/score.ts`, `src/bench/report.ts`, `test/normalize.test.ts`, `test/compare.test.ts`, `test/score.test.ts`
**Depends on:** `src/types.ts` and `runNonce` from Task 1. Runs in parallel with Task 2; touch nothing else.

`normalize.ts`:
- `export const NORMALIZATION_VERSION = "v1"` and `export const RULES: { name: string; rationale: string }[]` documenting every rule below (published with every score).
- `export function normalizeRecording(r: Recording): Recording` — returns a copy with every step body and event normalized using one per-recording context: anchor `t0` = the first integer `created` field found in step bodies in step order.
- Rules v1: (1) **ids**: any string matching `^([a-z]+(?:_[a-z]+)*)_(?=[A-Za-z0-9]*[A-Z0-9])[A-Za-z0-9]{10,}$` → `<id:PREFIX>` (the uppercase-or-digit lookahead keeps lowercase enum values such as `create_prorations`, `charge_automatically`, `default_incomplete` compared); (2) **timestamps**: integers in [946684800, 4102444800] under keys `created`, `date`, `start`, `end`, `start_date`, `due_date`, `billing_cycle_anchor`, `frozen_time`, `next_payment_attempt`, `effective_at`, or any key ending `_at`, `_start`, `_end`, `_date` → `<t:+Nh>` where N = round((t − t0)/3600); |t − t0| < 3600 → `<t:~0>`; (3) **run nonce**: any string containing `runNonce(r.runId, r.seq)` (import from `src/bench/run.ts`) has that substring replaced by `<run>`; (4) **secrets**: `client_secret` → `<secret>`; (5) **Stripe-hosted URLs**: strings starting `https://` whose host ends in `stripe.com` or `stripe.network` → `<url:HOST>`; (6) **opaque per-account values**: `fingerprint`, `invoice_prefix` → `<opaque>`; invoice `number` matching `^[A-Z0-9]+-\d+$` → `<number:-SUFFIX>` keeping the numeric suffix; (7) **lists**: for objects with `object` ∈ {`list`, `search_result`}, sort `data` by raw `created` descending, ties broken by the normalized element's JSON. Everything else is compared as-is (including `livemode`). Every rule's rationale must say what bug class it could hide.
- `export function normalizeRaw(r: Recording): Recording` — identity copy (used for the raw, un-normalized noise floor).

`compare.ts`:
- `export interface StepResult { i: number; L1: boolean; L2: boolean; L3: boolean }`
- `export interface SeqResult { seq: string; template: string; stratum: Stratum; heldOut: boolean; steps: StepResult[]; L4: boolean; eventsMatch: boolean; divergences: Divergence[] }`
- `export function compareRecordings(oracle: Recording, target: Recording, noise?: Set<string>): SeqResult` — inputs already normalized; pair steps by index. L1: status equal. L2: shape equal, where shape(null)="null", primitives → typeof, object → key→shape map, array → sorted unique element shapes. L3: deep-equal. L4: every step L3 **and** event types match as multisets. Divergences: status differs → one `STATUS_MISMATCH` at path `$` (skip body diff); otherwise walk both trees: key only in oracle → `MISSING_FIELD`; only in target → `EXTRA_FIELD`; differing primitives or type → `VALUE_MISMATCH`; array length differences reported at the array path as `VALUE_MISMATCH`; event type multiset differences → one `EVENT_SET_MISMATCH` at step −1 with `expected`/`actual` sorted type lists. Paths look like `$.items.data[0].price.unit_amount`. A divergence whose key `${template}|${step}|${path}` is in `noise` gets class `NONDETERMINISTIC` (it still counts against L2/L3/L4).
- `export function noiseKeys(results: SeqResult[]): Set<string>` — keys of all divergences from sandbox-vs-sandbox results.

`score.ts`:
- `export function wilson(k: number, n: number, z = 1.96): { p: number; lo: number; hi: number; k: number; n: number }` (n = 0 → p = lo = hi = 0).
- `export function score(results: SeqResult[]): Score` where `Score = { overall: LevelScores; byStratum: Record<string, LevelScores>; heldOut: LevelScores; train: LevelScores }` and `LevelScores = Record<Level, ReturnType<typeof wilson>>`; L1–L3 are step-level proportions, L4 sequence-level.

`report.ts`:
- `export function renderMarkdown(input: { title: string; date: string; target: string; oracle: string; score: Score; noise?: Score; normalization: string; results: SeqResult[] }): string` — sections: summary line (overall L1–L4 with CIs), noise floor (1 − noise agreement per level) and ceiling (= noise agreement) when `noise` present, per-stratum table (L1–L4 as `pct [lo–hi] (n)`), held-out vs train, top 20 divergence paths by count with class and one example, per-template L4, normalization version with rule names. States plainly: "Any score without the noise floor and ceiling is invalid" when `noise` is absent.
- `export function toJson(...)` — same inputs as a plain object (for `report.json`).

Tests: hand-built `Recording` fixtures (no network) covering each normalization rule (including the list sort and the t0 anchor), each divergence class, L4 failing only on events, noise keys marking `NONDETERMINISTIC`, Wilson values checked against known numbers (e.g. k=8, n=10 → lo≈0.4902, hi≈0.9433), and a Markdown snapshot-ish check that required sections exist.

## Task 4: Oracle hygiene (read budget, event sweep, normalization v1.1)

**Paths:** `src/bench/run.ts`, `src/bench/normalize.ts`, `src/bench/compare.ts`, `src/bench/report.ts`, `src/bench/budget.ts`, `src/types.ts`, `test/run.test.ts`, `test/normalize.test.ts`, `test/compare.test.ts`, `test/budget.test.ts`
**Depends on:** Tasks 1–3. **Why:** `docs/decisions/0001-clean-room-and-legal-gate.md` C2 — Stripe's rate-limits page says read (GET) requests "must not exceed" an allocation with a floor of 10,000 per rolling 30 days; until Stripe confirms sandboxes are exempt we budget ≤10,000 sandbox GETs per 30 days. Per-sequence `/v1/events` polling (≥2 GETs per sequence) cannot fit a nightly corpus.

1. **Corpus-level event sweep.** `runSequence` gets an option `collectEvents?: boolean` (default `true`, current per-sequence behavior, kept for single-sequence re-runs). `runCorpus` runs sequences with `collectEvents: false`, then performs ONE sweep: wait `target.eventWaitMs`, list `GET /v1/events?created[gte]=<corpusStartSec-60>&limit=100` with pagination (no page cap; the corpus defines the volume), repeat the full sweep every 3 s until the total count is unchanged across two consecutive sweeps or 30 s have passed, then assign events to each recording with the existing id-set filter (same sort). An event may belong to several recordings only if their id sets overlap (they should not; count and report overlaps in the run summary).
2. **Events failure marker.** Add `eventsError?: string` to `Recording` in `src/types.ts`. Set it when event collection fails (non-200 after retries, transport or parse error) — never silently `[]`. `compareRecordings` skips the event comparison when either side has `eventsError` (sets `eventsMatch: true`, adds no divergence) and `SeqResult` gains `eventsSkipped: boolean`; the Markdown report states how many sequences skipped the event check. *(Changed 2026-09-26, final review: only the oracle side's failure skips the check. A target whose collection fails gets `eventsMatch: false` and an EVENT_SET_MISMATCH with actual `error: <message>`, so a broken `/v1/events` can never score better than a working one.)*
3. **Request accounting.** `runCorpus` returns (or exposes via a second return value / callback) a run summary: `{ requests, gets, posts, deletes, eventSweepGets, retries429 }`, counting every HTTP request actually sent including retries and event pages. Event-poll 429 retries are counted.
4. **Read budget ledger** in `src/bench/budget.ts`: `readLedger(path)`, `rollingGets(entries, nowIso, days = 30)`, `appendLedger(path, entry)` where entry = `{ date: ISO, account: string, target: string, runId: string, gets: number, posts: number, deletes: number, charges: number }` (JSONL; counts only, never response data). `charges` = number of `charge.succeeded` events observed (lets us report reads per transaction). Unit-tested with fixed dates.
5. **Normalization v1.1** (`NORMALIZATION_VERSION = "v1.1"`, RULES updated with rationale): (a) rule 1 also replaces id tokens embedded inside longer strings (word-bounded, same prefix/tail/lookahead grammar), e.g. `"No such customer: 'cus_ABC123…'"` → `"No such customer: '<id:cus>'"`; (b) new rule: strip the exact prefix `"This is an unclaimed Stripe sandbox. Dashboard links in this error message will not work until the sandbox is claimed. "` from strings (account-state banner, not API behavior; disappears once the sandbox is claimed).
6. **Small fixes from Task 1/3 reviews:** event tie-break uses code-point comparison (`a < b`), not `localeCompare`; the limiter test drops its `< 1500 ms` upper bound; the live test reports "STRIPE_API_KEY is not set" instead of throwing ENOENT when `.env` is absent; the Markdown top-divergence table lists `NONDETERMINISTIC` rows after all other classes.

Tests: sweep assignment against the local fake server (two sequences, interleaved events, one sweep), `eventsError` set on a 500 from `/v1/events` and comparison skipped, request accounting counts retries and event pages, embedded-id normalization, banner stripping, ledger rolling sum across a 30-day boundary.

## Task 5: CLI and W0 oracle measurements
