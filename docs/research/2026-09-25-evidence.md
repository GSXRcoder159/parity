# Evidence base for the Parity MVP plan (2026-09-25)

Compiled from four web-research passes (Stripe facts, competitors, methods, demand) plus user-supplied links. Items marked UNVERIFIED were not confirmed from a primary source and are on the W0 verification list.

## 1. Stripe sandbox facts (primary: docs.stripe.com, github.com/stripe)

- **Rate limits:** live 100 req/s, sandbox 25 req/s; per-endpoint default 25 req/s; Subscriptions API: 10 new invoices per subscription per minute, 20 per day, 200 quantity updates per subscription per hour; PaymentIntents 1,000 updates per PI per hour. https://docs.stripe.com/rate-limits
- **Load testing policy (verbatim):** "We generally discourage this practice because API limits are lower in a sandbox... we recommend building integrations so that they have a configurable system for mocking out requests to the Stripe API, which you can enable for load tests." https://docs.stripe.com/rate-limits
- **Sandboxes:** isolated data per sandbox; up to 5 per account (UNVERIFIED against primary text); `stripe sandbox create` provisions "an anonymous Stripe sandbox with working API keys. No account registration required." Claimable Sandboxes v2 API exists (not read). https://docs.stripe.com/sandboxes , https://docs.stripe.com/api/v2/claimable-sandboxes
- **Test clocks:** up to 3 customers, 3 subscriptions per customer, 10 unattached quotes per clock; advance ≤2 periods per call (≤2 years with no subscriptions); "it takes a few seconds to advance"; events `test_helpers.test_clock.advancing` / `.ready`; clocks auto-delete after 30 days; repeated calls against a frozen subscription can trigger `rate_limit` errors. https://docs.stripe.com/billing/testing/test-clocks/api-advanced-usage
- **stripe-mock (verbatim):** "stripe-mock is stateless. Data you send on a POST request will be validated, but it will be completely ignored beyond that." and "We are currently not planning to add statefulness or more sophisticated testing features to stripe-mock." 1,647 stars, MIT, pushed 2026-09-25. https://github.com/stripe/stripe-mock
- **OpenAPI spec:** `spec3.json`/`.yaml`, fixtures keyed by `x-resourceId`, `/latest/` recommended; generated by a closed-source generator. License: UNVERIFIED. https://github.com/stripe/openapi
- **Versioning:** current `2026-08-26.dahlia`; monthly additive versions, two breaking major releases per year. No RSS/JSON changelog feed found (UNVERIFIED). https://docs.stripe.com/api/versioning , https://docs.stripe.com/changelog
- **Webhooks (verbatim):** "Stripe doesn't guarantee the delivery of events in the order that they're generated." Sandbox retries "three times over the course of a few hours." `GET /v1/events` lists 30 days, cursor pagination, up to 20 `types`. https://docs.stripe.com/webhooks
- **Idempotency:** keys pruned after ≥24 h; same key with different parameters errors; first result (including 500s) is replayed; POST only. https://docs.stripe.com/api/idempotent_requests
- **Terms:** SSA §2.4 reportedly bars reverse engineering / derivative works of "Stripe Technology"; §1.2(a)(iv) bars interfering with the Services. Retrieved via a summarizer, so wording is UNVERIFIED; no clause found that bans building a mock or benchmarking the sandbox. Read directly in W0. https://stripe.com/legal/ssa
- **Stripe's own guidance:** use separate sandboxes for local dev and CI. https://docs.stripe.com/billing/testing ; agent-billing workflows page https://docs.stripe.com/agents-billing-workflows

## 3. Methods

- **MIRAGE (arXiv 2604.04806):** key-level pass = valid JSON + status sequence matches + recursive key/type/shape match; total pass adds caller-observable value faithfulness via a 3-gate checker (structural → pattern match → two-judge LLM panel). White-box 99% status / 99% shape vs record-replay 62% / 16%; record-replay ≈0–1% total pass on error/edge cases. Scenarios (110) were hand-designed across 9 behavior categories. https://arxiv.org/abs/2604.04806
- **Vera / "Automated Synthesis of Cloud Emulators" (arXiv 2608.23842):** resources as state machines; symbolic scaffold (~7k lines) + LLM-filled behavior; alignment loop = trace alignment on logical resources → earliest root-cause discrepancy → classes MISSING_FIELD / EXTRA_FIELD / VALUE_MISMATCH / STATUS_MISMATCH → symbolic repair first (response seeding) then LLM repair → re-run. ~1.3 h synthesis for EC2; 80% of 260 AWS CLI commands vs LocalStack 47%. Limitations: no latency/rate-limit modeling, periodic relearning needed. https://arxiv.org/abs/2608.23842 , https://github.com/project-vera/vera (license UNVERIFIED)
- **RESTler (MIT):** infers producer/consumer dependencies from OpenAPI and generates stateful sequences; reusable idea for v1 probe generation. https://github.com/microsoft/restler-fuzzer
- **Schemathesis (MIT, Python)** stateful links; **EvoMaster** white-box needs JVM instrumentation. https://schemathesis.io , https://arxiv.org/pdf/2205.05325
- **Diff triage:** Godefroid et al., Differential Regression Testing for REST APIs (ISSTA 2020) normalizes timestamps/ids/nondeterministic enums; Signadot relevancy-weighted diffs. https://patricegodefroid.github.io/public_psfiles/issta2020.pdf , https://www.signadot.com/blog/rest-api-testing-using-relevancy-weighted-diffs
- **Poesia:** Minimo (arXiv 2407.00695) conjecture-and-prove self-play with type-directed generation and library learning; "Automated Discovery of Tactic Libraries" (2025); dafny-annotator. Mapping: conjecture = API sequence typed by the OpenAPI schema, reward = novel state + disagreement risk. https://gpoesia.com/ , https://github.com/gpoesia/minimo
- **nsync:** benchmark for Terraform/AWS drift detection via controlled mutations; template for testing the drift instrument. https://github.com/zyang37/nsync
- **exo (MIT, Rust+TS):** self-modifying agent harness with an append-only, agent-immutable event log as audit trail; design reference for the sealed log. https://github.com/exoharness/exo
- **Jev (typesafe.ai):** typed, calibrated decisions; vendor claims 70–500 ms latency, $0.042/MTok input (UNVERIFIED). Candidate for cheap triage. https://typesafe.ai/blog/introducing-system-one-models-and-jev
- **YC RFS "Self-Maintaining APIs" (verbatim excerpt):** "When Stripe ships a breaking change or a new feature, an agent should scan customer codebases, identify affected usages, and open a PR with the fix... or as a neutral third-party service tracking changes across vendors, like Dependabot but for APIs." https://www.ycombinator.com/rfs
- **Superdark Factory (Antikythera):** essay on "the dark stack"; positioning material only. https://superdark.antikythera.org/
